== Einführung in Git

=== Was ist Git?

Git ist ein verteiltes Versionskontrollsystem, das von Linus Torvalds entwickelt wurde, um die Entwicklung des Linux-Kernels zu verwalten. Es ermöglicht die Nachverfolgung von Änderungen an Dateien und die Zusammenarbeit mehrerer Entwickler an einem Projekt.

=== Warum Versionskontrolle?

* *Zeitreisen durch Code*: Jeder Stand des Projekts kann wiederhergestellt werden
* *Kollaboration*: Mehrere Entwickler können gleichzeitig an einem Projekt arbeiten
* *Fehleranalyse*: Nachvollziehen, wann und warum Fehler eingeführt wurden
* *Experimentieren*: Neue Funktionen können in separaten Branches entwickelt werden

== Git Workflows

=== Zentrale Workflows

[cols="1,3", options="header"]
|===
| Workflow | Beschreibung
| Centralized Workflow | Ein zentrales Repository, an dem alle Entwickler arbeiten
| Feature Branch Workflow | Jede neue Funktion wird in einem separaten Branch entwickelt
| Gitflow Workflow | Strengerer Workflow mit definierten Branch-Typen
| Forking Workflow | Jeder Entwickler hat sein eigenes öffentliches Repository
|===

image::gitflow-example.png[Git Flow Beispiel,800,align="center"]

=== Gitflow im Detail

Der Gitflow-Workflow ist besonders für Projekte mit regelmässigen Releases geeignet:

* `main`/`master`: Enthält die Produktionsreleases
* `develop`: Hauptentwicklungszweig
* `feature/`: Für neue Funktionen
* `release/`: Für die Vorbereitung neuer Releases
* `hotfix/`: Für dringende Korrekturen am Produktivcode

[source,bash]
----
# Beispiel: Neuen Feature-Branch erstellen
git checkout develop
git checkout -b feature/neue-funktion
----

== Installation und Erste Schritte

=== Systemvoraussetzungen

* Mindestens 100 MB freier Festplattenspeicher
* Internetverbindung für den Download
* Terminal/Command Line Zugriff

=== Plattformspezifische Installation

=== Windows

1. Lade den Installer von https://git-scm.com/downloads[Git für Windows] herunter
2. Führe die .exe-Datei aus und folge den Anweisungen
3. Wähle "Git from the command line and also from 3rd-party software"
4. Nach der Installation öffne Git Bash oder die Eingabeaufforderung

=== Linux

[source,bash]
----
# Debian/Ubuntu
sudo apt update
sudo apt install git

# Fedora
sudo dnf install git

# Arch Linux
sudo pacman -S git
----

=== macOS

1. Installiere Homebrew falls noch nicht vorhanden:
[source,bash]
----
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
----
+
2. Installiere Git:
[source,bash]
----
brew install git
----

=== Erste Schritte nach der Installation

Konfiguriere deine Benutzerdaten:
[source,bash]
----
git config --global user.name "Dein Name"
git config --global user.email "deine.email@beispiel.ch"
# Standard-Editor auf VS Code setzen
git config --global core.editor "code --wait"
----

=== Verzeichnisstruktur verstehen

Ein typisches Git-Repository enthält:

* `.git/`: Verzeichnis mit allen Metadaten
* `HEAD`: Zeiger auf den aktuellen Branch
* `config`: Repository-Konfiguration
* `objects/`: Enthält alle Repository-Daten
* `refs/`: Zeiger auf Commit-Objekte

== Git Befehle im Überblick

=== Repository erstellen und klonen

[cols="1,3", options="header"]
|===
| Befehl | Beschreibung
| `git init` | Erstellt ein neues Git-Repository im aktuellen Verzeichnis
| `git clone <url>` | Klont ein bestehendes Repository
|===

=== Grundlegende Workflow-Befehle

[cols="1,3", options="header"]
|===
| Befehl | Beschreibung
| `git status` | Zeigt den aktuellen Status des Arbeitsverzeichnisses
| `git add <datei>` | Fügt Änderungen zur Staging-Area hinzu
| `git commit -m "Nachricht"` | Erstellt einen Commit mit den gestagten Änderungen
| `git push` | Überträgt lokale Commits zum Remote-Repository
| `git pull` | Holt Änderungen vom Remote-Repository und führt sie zusammen
|===

=== Branching und Merging

[cols="1,3", options="header"]
|===
| Befehl | Beschreibung
| `git branch` | Zeigt alle lokalen Branches an
| `git branch <name>` | Erstellt einen neuen Branch
| `git checkout <branch>` | Wechselt zu einem anderen Branch
| `git merge <branch>` | Führt einen Branch in den aktuellen Branch zusammen
| `git rebase <branch>` | Wendet Commits auf einen anderen Basis-Branch an
|===

=== Fortgeschrittene Befehle

[cols="1,3", options="header"]
|===
| Befehl | Beschreibung
| `git stash` | Speichert nicht-committete Änderungen temporär
| `git cherry-pick <commit>` | Übernimmt spezifische Commits in den aktuellen Branch
| `git reset` | Setzt den aktuellen HEAD auf einen bestimmten Zustand zurück
| `git reflog` | Zeigt eine Chronik aller Git-Aktionen
| `git bisect` | Hilft bei der Fehlersuche durch binäre Suche
|===

=== Nützliche Aliase

Füge diese zu deiner `~/.gitconfig` hinzu, um Zeit zu sparen:

[source,ini]
----
[alias]
    co = checkout
    br = branch
    ci = commit
    st = status
    last = log -1 HEAD
    lg = log --graph --pretty=format:'%Cred%h%Creset -%C(yellow)%d%Creset %s %Cgreen(%cr) %C(bold blue)<%an>%Creset' --abbrev-commit
----

== Best Practices für sinnvolle Commits

=== Warum gute Commit-Messages wichtig sind

* Erleichtern die Zusammenarbeit im Team
* Ermöglichen schnelles Verstehen von Änderungen
* Erleichtern das Debuggen von Problemen
* Helfen bei der automatischen Generierung von Changelogs

=== Die Kunst des Committerns

Gute Commit-Messages folgen dem Schema der https://www.conventionalcommits.org/[Conventional Commits] und beinhalten:

1. Einen Typ (type): Beschreibt die Art der Änderung
2. Einen Scope (optional): Gibt den betroffenen Teil des Codes an
3. Eine kurze Beschreibung (max. 50 Zeichen)
4. Einen ausführlicheren Beschreibungsteil (wenn nötig)
5. Einen Footer für Breaking Changes oder Issue-Referenzen

=== Beispiel für eine gute Commit-Message

[source,text]
----
feat(auth): implementiere Zwei-Faktor-Authentifizierung

- Füge 2FA-Implementierung mit TOTP hinzu
- Erweitere Benutzerprofil um 2FA-Einstellungen
- Füge Tests für die neue Funktionalität hinzu

Closes #123
BREAKING CHANGE: Die Login-API erfordert nun ein zusätzliches TOTP-Token
----

=== KI-Unterstützung für Commit-Messages

Mit folgendem Prompt kannst du KI-Tools wie GitHub Copilot oder ChatGPT nutzen, um dir bei der Erstellung von Commit-Messages zu helfen:

[source,text]
----
Du bist mein Unterstützer in der Herstellung von guten Git-Commit-Meldungen nach den Prinzipien der "Conventional Commits" (https://www.conventionalcommits.org/).

Wir verwenden folgendes Format:

type: Kurze Beschreibung

Detaillierte Erklärung
- Änderung 1
- Änderung 2
- ...
- Änderung n

Verfügbare Types:

- `feat:` - Neue Features
- `fix:` - Bugfixes
- `docs:` - Dokumentationsänderungen
- `chore:` - Wartungsarbeiten
- `refactor:` - Code-Refactoring
- `test:` - Test-bezogene Änderungen

---

Für die Erstellung deiner Git-Commit-Meldungen werde ich dir jeweils ein `git diff` zur Verfügung stellen.
----

== Fortgeschrittene Themen

=== Git Hooks

Automatisiere wiederkehrende Aufgaben mit Git Hooks:

* `pre-commit`: Wird vor dem Commit ausgeführt
* `pre-push`: Wird vor dem Push ausgeführt
* `commit-msg`: Wird nach dem Schreiben der Commit-Nachricht ausgeführt

Beispiel für einen einfachen `pre-commit` Hook:
[source,bash]
----
#!/bin/sh
# Prüfe auf Debug-Ausgaben
if git diff --cached --name-only | xargs grep -n "console.log"
then
    echo "Warnung: console.log-Aufrufe gefunden!"
    exit 1
fi
----

=== Git Submodule

Verwende Submodule, um externe Abhängigkeiten zu verwalten:
[source,bash]
----
# Submodule hinzufügen
git submodule add https://github.com/beispiel/externes-repo.git pfad/zum/submodule

# Repository mit Submodulen klonen
git clone --recurse-submodules https://github.com/beispiel/repo.git
----

=== Git LFS für grosse Dateien

Für die Versionierung grosser Dateien:
[source,bash]
----
# Git LFS installieren
git lfs install

# Bestimmte Dateitypen verfolgen
git lfs track "*.psd"
git lfs track "*.mp4"
----
